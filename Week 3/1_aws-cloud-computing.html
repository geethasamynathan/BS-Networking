1. What is cloud computing?

Cloud computing is the on-demand delivery of computing resources—servers, storage, networking, databases, software, and more—over the internet, typically with usage-based pricing.

Before cloud: on-premises IT

To launch an online shopping application, an organization traditionally buys and houses physical servers, installs operating systems, configures networks, manages software, provides backups, and maintains hardware, cooling, power, and security.

With AWS cloud

Instead of purchasing servers, you provision virtual infrastructure and managed services on demand. AWS operates the underlying data centers; you manage the responsibilities for the services you select.

2. What is Amazon Web Services (AWS)?

AWS stands for Amazon Web Services, Amazon's cloud platform offering 200+ services spanning compute, storage, networking, databases, security, analytics, machine learning, and more.

Organizations use AWS to host .NET, Java, Python and Node.js applications; store files; run databases; build data pipelines; implement APIs; monitor systems; and create AI applications.

3. What are IaaS, PaaS and SaaS?

These three cloud service models indicate which parts of a technology solution the provider manages versus what the customer manages.

IaaS — Infrastructure as a Service

Rent infrastructure such as virtual machines, networking and disks. You install and manage the guest OS, runtime, and application.

AWS example: Amazon EC2

PaaS — Platform as a Service

Use a managed application platform. You focus mainly on application code and configuration rather than directly managing servers.

AWS example: Elastic Beanstalk

SaaS — Software as a Service

Use a completed application operated by the software provider. You mainly configure and consume it.

Examples: Amazon WorkMail, Microsoft 365, Salesforce

4.1 IaaS example: EC2 + Java application

  1. Create an EC2 virtual machine.
  2. Select an OS such as Ubuntu.
  3. Install Java, Nginx and application dependencies.
  4. Deploy the Spring Boot application JAR.
  5. Configure network rules, patching, backup and monitoring.

AWS supplies the underlying hardware and virtualization; your team manages the guest OS and application.

4.2 PaaS example: Elastic Beanstalk

  1. Package your supported application.
  2. Choose a supported platform environment.
  3. Upload and deploy the application.
  4. Configure variables, health checks and scaling.

Elastic Beanstalk orchestrates underlying AWS resources, but those resources may still incur charges and you still own application-level security.

4.3 SaaS example: business email

Employees use a hosted email service without building or managing a mail server. The provider operates the application, while the company manages identity, accounts, access and data governance as applicable.

5. AWS Global Infrastructure

Region: A distinct geographic area containing AWS infrastructure (for example, Mumbai ap-south-1 and Hyderabad ap-south-2).

Availability Zone (AZ): One or more data centers with independent infrastructure within a Region, designed for fault isolation.

Edge location: A location used by services such as CloudFront to deliver content close to viewers.

Diagram 3 — Region → Availability Zones → Data Centers
AZ labels shown are illustrative; account-specific names and mappings can vary.

Why multiple AZs?

If an application relies on one server in a single AZ, that server or AZ can become a single point of failure. A resilient deployment distributes compute across AZs and uses load balancing and an appropriate database availability configuration.

16. Beginner hands-on lab — IAM, Billing and S3

Hands-on Objective: Learn console navigation, Regions, cost alerts, S3 buckets and object upload without needing to launch a server.

Step 1 — Sign in to AWS

Visit AWS Management Console. If you need a new account, carefully review current sign-up, credits, Free Tier and payment terms.

Step 2 — Choose Region

Open the Region menu. For an India lab, you may choose Asia Pacific (Mumbai) ap-south-1, subject to suitability and available services.

Step 3 — Secure access

Enable MFA for the root user. Use properly permissioned IAM or IAM Identity Center access for routine operations. Never put credentials in source code.

Step 4 — Create a budget alert

Open Billing and Cost Management → Budgets. Create a monthly cost budget and email notification for a suitable threshold (for example, $5). A budget alert is not a hard cost cap.

Step 5 — Create an S3 bucket

  1. Search for S3 in the console.
  2. Select Create bucket.
  3. Choose the appropriate Region.
  4. Enter a globally unique name, e.g. swiftbasket-training-unique-id.
  5. Keep Block all public access enabled.
  6. Use the default encryption setting and create the bucket.

Step 6 — Upload sample CSV data

ProductID,ProductName,Price,Category

102,Mouse,500,Electronics

Save as products.csv, open your bucket, choose Upload → Add files and upload it. Discuss buckets, objects, keys, permissions, encryption and versioning.

Step 7 — Lab cleanup

Delete the uploaded object and empty bucket when finished. Inspect the billing dashboard and remaining resources.
