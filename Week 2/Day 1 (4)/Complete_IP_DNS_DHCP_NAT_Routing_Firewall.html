Complete Networking Tutorial: IP Addressing, DNS, DHCP, NAT, Routing, Ports and Firewalls

Practical Linux / Ubuntu Networking — Real-World Corporate Scenarios, Architecture, Commands, Expected Outputs and Troubleshooting

1. Understanding networking through a real-world story

Imagine you joined TechNova Solutions, an IT company with 100 employees, as a Linux System Administrator. The company has a website, an internal application, a database server and employees connecting to the internet. One morning, your manager asks you to:

  1. Assign an IP address to every computer.
  2. Allow employees to access the company website by its name.
  3. Automatically assign network settings when employees connect.
  4. Allow employees to share a public internet connection.
  5. Connect the HR and IT department networks.
  6. Run applications on different ports.
  7. Protect servers from unauthorized connections.
Requirement Networking concept
Identify every computer IP Addressing
Find websites by name DNS
Automatically assign addresses DHCP
Share internet access NAT
Connect multiple networks Routing
Identify application services Ports
Allow/block network traffic Firewall

Module 1 — IP Addressing

4. What is an IP address?

IP means Internet Protocol. Like an office desk number helps locate an employee, an IP address identifies an interface used for network communication. Example: Computer A = 192.168.10.10; Computer B = 192.168.10.20.

An IP packet includes source and destination IP addresses. On an Ethernet LAN, ARP normally resolves a neighboring IPv4 address (destination or next hop) to a MAC address.

5. Types of IP addresses

Private addresses: Used inside offices, homes and internal cloud networks. Examples: 192.168.1.10, 10.0.0.10, 172.16.5.20.

RFC 1918 private range Prefix
10.0.0.0 – 10.255.255.255 /8
172.16.0.0 – 172.31.255.255 /12
192.168.0.0 – 192.168.255.255 /16

Public addresses: Used for publicly routable internet communication. Documentation examples: 203.0.113.10 and 198.51.100.25 (not real public IPs to deploy).

Static IP: Configured manually or permanently reserved; typical for servers and routers. Dynamic IP: Automatically supplied, often via DHCP; typical for laptops.

Consider 192.168.10.10/24. /24 means that 24 of the 32 IPv4 bits describe the network prefix.

Network Address  : 192.168.10.0
Broadcast Address: 192.168.10.255
Usable Hosts     : 192.168.10.1 - 192.168.10.254

Lab — Test loopback:

ping -c 4 127.0.0.1

Typical output:

64 bytes from 127.0.0.1: icmp_seq=1 ttl=64 time=0.04 ms
64 bytes from 127.0.0.1: icmp_seq=2 ttl=64 time=0.03 ms

This checks the local TCP/IP stack, not internet connectivity.

Test external IP reachability:

ping -c 4 1.1.1.1

A failed ping may mean that ICMP is filtered, not necessarily that the internet is unavailable.

Industry story: A new employee cannot access internal applications. First inspect laptop IP, subnet and default gateway.

Module 2 — DNS (Domain Name System)

8. What is DNS?

DNS helps translate domain names to IP addresses and provides other records. An employee enters https://www.example.com and the computer discovers which address to contact. Think of DNS as a telephone directory for names.

9. How DNS resolution works

  1. Employee enters a website name.
  2. The OS checks local sources such as caches and hosts-file mappings where applicable.
  3. If needed, a query goes to the configured resolver.
  4. The resolver uses cache or queries the DNS hierarchy.
  5. DNS returns an appropriate answer.
  6. The browser connects to an address returned for the website.

The public DNS hierarchy includes root, top-level-domain and authoritative name servers.

10. DNS hands-on lab

Step 1 — Inspect DNS configuration:

cat /etc/resolv.conf

Example:

Step 2 — Resolve a name:

Illustrative output (actual IP varies):

Address:        10.255.255.254#53

Step 4 — Query other record types:

dig gmail.com MX
dig example.com NS
dig example.com TXT

11. Local name resolution with /etc/hosts

Step 1 — Add local name:

echo "127.0.0.1 training.test" | sudo tee -a /etc/hosts

Step 2 — Verify:

getent hosts training.test

Expected:

127.0.0.1 training.test

Step 3 — Test:

ping -c 2 training.test

The name maps to the local machine. This is hosts-file resolution, not a DNS server; dig may not show this mapping because it queries DNS.

Remove test entry:

sudo sed -i '/^127\.0\.0\.1 training\.test$/d' /etc/hosts

Industry story: portal.company.example fails while its IP works. Investigate resolver, DNS entries, cache, search domains and local overrides.

Module 3 — DHCP (Dynamic Host Configuration Protocol)

12. What is DHCP?

Your company hires 100 employees. Without DHCP, the administrator may manually set IP address, subnet mask, default gateway and DNS for every laptop. DHCP automatically supplies network configuration. Think of it as a reception desk allocating temporary desk numbers.

13. DORA — How DHCP works

The DHCP server can be configured with:

Subnet           : 192.168.10.0/24
DHCP Pool Start  : 192.168.10.100
DHCP Pool End    : 192.168.10.200
Gateway          : 192.168.10.1
DNS Server       : 192.168.10.53
Lease Duration   : 24 hours

Example laptop settings:

IP Address       : 192.168.10.101
Subnet Mask      : 255.255.255.0
Default Gateway  : 192.168.10.1
DNS Server       : 192.168.10.53

Leases are temporary and normally renewed before expiration. DHCPv4 uses UDP 67 (server) and 68 (client).

14. DHCP verification commands

Ubuntu:

ip -4 addr
ip route
cat /etc/resolv.conf

On systems with NetworkManager:

nmcli device status
nmcli device show

On systems using systemd-networkd:

networkctl status

These may be unavailable or provide limited details on WSL.

Windows PowerShell:

ipconfig /all

Example:

DHCP Enabled     : Yes
DHCP Server      : 192.168.1.1
IPv4 Address     : 192.168.1.105
Default Gateway  : 192.168.1.1

15. Real DHCP server configuration (isolated Ubuntu VM only)

Safety: Never run an experimental DHCP server on the active corporate LAN or ordinary WSL instance; use a private lab network with no competing DHCP server.

sudo apt install isc-dhcp-server

Example /etc/dhcp/dhcpd.conf:

authoritative;
default-lease-time 3600;
max-lease-time 86400;

subnet 192.168.10.0 netmask 255.255.255.0 {
    range 192.168.10.100 192.168.10.150;
    option routers 192.168.10.1;
    option domain-name-servers 192.168.10.53;
    option subnet-mask 255.255.255.0;
}

Choose a VM interface already connected to your isolated test subnet and configure the server's static IP there. Example /etc/default/isc-dhcp-server:

INTERFACESv4="enp0s8"

enp0s8 is illustrative. Validate, start and inspect:

sudo dhcpd -t -cf /etc/dhcp/dhcpd.conf
sudo systemctl restart isc-dhcp-server
sudo systemctl status isc-dhcp-server
sudo cat /var/lib/dhcp/dhcpd.leases

Industry story: New laptops cannot obtain addresses. Check pool exhaustion, lease status, network connectivity, DHCP relay and server logs.

Module 4 — NAT (Network Address Translation)

16. Why do we need NAT?

The company has 100 laptops with private IPv4 addresses but only one public IPv4 address. Standard IPv4 internet access commonly uses PAT (Port Address Translation), also called NAT overload, allowing many internal devices to share one public address.

17. NAT storytelling example

Example translation state:

Internal source Translated public source
192.168.10.10:51001 203.0.113.10:61001
192.168.10.11:51001 203.0.113.10:61002
192.168.10.12:51001 203.0.113.10:61003

These are documentation examples, not real public endpoints.

  1. Employee A opens a connection from 192.168.10.10:51001.
  2. The NAT gateway translates the source to 203.0.113.10:61001.
  3. The internet server receives the translated connection.
  4. It replies to the public IP and port.
  5. The gateway looks up its translation state.
  6. Return traffic reaches Employee A.

Protocol and destination details can also be tracked by PAT.

18. NAT hands-on verification

hostname -I
curl -4 https://api.ipify.org

Illustrative comparison:

Linux IP         : 172.28.96.10
Observed Public  : 198.51.100.25

The example public IP is reserved for documentation. The externally observed address may differ due to NAT, VPN or a proxy. Ordinary WSL2 NAT can introduce one translation at Windows plus another at the home/office router.

19. SNAT vs DNAT

Type Purpose Example
SNAT Changes source address Laptop reaching internet
DNAT Changes destination address Public request forwarded to internal web server
PAT Translates addresses and ports Multiple laptops share public IPv4

Port-forwarding example: A gateway receives traffic on public port 8080 and forwards it to internal 192.168.10.20:80. This needs a DNAT rule and compatible firewall permissions on infrastructure you control.

Public IP:8080
     |
     v
192.168.10.20:80

Industry story: An internal application works on office Wi-Fi but not from outside. Check public IP, destination NAT, forwarding permissions, firewall, server listening socket and ISP restrictions.

Module 5 — Routing Basics

20. What is routing?

Routing selects where to forward IP packets. TechNova has IT network 192.168.10.0/24 and HR network 192.168.20.0/24. Their hosts cannot communicate directly as same-subnet peers; a router or Layer 3 switch forwards between them.

21. Routing architecture

  1. The IT laptop sees that HR's destination IP is outside its subnet.
  2. It forwards the packet toward 192.168.10.1.
  3. The router checks its routing table.
  4. The router forwards to the HR subnet.
  5. The HR host receives the packet.
  6. An appropriate return route delivers the reply.

22. Understanding the Linux routing table

ip route

Illustrative output:

default via 192.168.10.1 dev eth0
192.168.10.0/24 dev eth0 proto kernel scope link src 192.168.10.10
Entry Meaning
default Fallback route for destinations without a more specific match
via 192.168.10.1 Next-hop gateway
dev eth0 Outgoing interface
192.168.10.0/24 Directly connected subnet
src 192.168.10.10 Preferred source IP

Default IPv4 route means 0.0.0.0/0.

Find the chosen route:

ip route get 1.1.1.1

Example:

1.1.1.1 via 192.168.10.1 dev eth0 src 192.168.10.10

23. Static routing demonstration

If a real lab router for HR is reachable at 192.168.10.2, an example route is:

sudo ip route add 192.168.20.0/24 via 192.168.10.2
ip route show
sudo ip route del 192.168.20.0/24 via 192.168.10.2

Caution: Do not add the route on your active WSL or office computer unless this gateway exists. Routing must also work on the return path. ip route add changes the current routing table and is normally nonpersistent.

24. Trace a route

traceroute example.com
traceroute -n 1.1.1.1

Example:

1  192.168.10.1
2  10.10.1.1
3  *
4  1.1.1.1

A * means no probe response arrived before timeout, not necessarily that data cannot cross that hop.

25. Static vs dynamic routing

Static routing Dynamic routing
Manually configured Routers exchange routes
Suitable for simple networks Useful for larger networks
No routing protocol needed Protocols include OSPF and BGP
Requires manual changes Can adapt to topology changes

Industry story: HR cannot access an IT application. Check network prefixes, gateways, routing and return routes, and firewall policy.

Module 6 — Ports and Network Services

26. What is a port?

The IP address locates a network interface, but a server may run many services: SSH, a website, APIs and databases. Transport-layer port numbers help distinguish the intended service. Think of an office building address (IP) and department extension numbers (ports).

A socket or connection is identified by more than its port: transport protocol and source/destination addresses and ports matter.

27. Important TCP and UDP ports

Port Transport Common service
20, 21 TCP FTP (classic data/control)
22 TCP SSH
25 TCP SMTP
53 UDP/TCP DNS
67, 68 UDP DHCPv4
80 TCP HTTP
110 TCP POP3
123 UDP NTP
143 TCP IMAP
443 TCP/UDP HTTPS, including HTTP/3 over UDP
445 TCP SMB
3306 TCP MySQL
3389 TCP/UDP RDP
5432 TCP PostgreSQL
6379 TCP Redis
8080 TCP Alternate HTTP port

These are common/default assignments; individual apps can use different ports.

Step 6 — Inspect listening sockets:

ss -lntp

LISTEN 0 5 127.0.0.1:8080 0.0.0.0:*
Field Meaning

29. TCP vs UDP

TCP UDP
Reliable ordered byte stream Connectionless datagrams
Uses handshake, acknowledgements and retransmission No built-in guarantee of delivery or ordering
Examples: SSH, PostgreSQL, HTTP/1.1, HTTP/2 Examples: DHCP, many DNS queries, QUIC/HTTP/3

Inspect TCP/UDP:

ss -lnt
ss -lun
ss -tuna
sudo ss -tulpn

Check a TCP service: Start the Python HTTP server again in one terminal and run:

nc -vz 127.0.0.1 8080

Example:

Connection to 127.0.0.1 8080 port [tcp/*] succeeded!

This shows the TCP connection worked, not necessarily application health or security.

Module 7 — Firewall Concepts

30. What is a firewall?

A firewall controls incoming and outgoing network traffic based on rules. For TechNova: public website traffic can reach 80/443, SSH 22 is restricted to administrators, and PostgreSQL 5432 stays internal.

31. How firewall rules work

A firewall evaluates packets against a policy, such as allow TCP 443, restrict TCP 22 to the admin subnet, deny unauthorized connections to TCP 5432. Stateful firewalls can track established connections and allow appropriate return traffic.

32. Firewall terminology

Term Meaning
Inbound Traffic arriving at host/network
Outbound Traffic leaving host/network
Allow Permit matching traffic
Deny/Drop Block matching traffic
Reject Explicitly refuse traffic where supported
Stateful Track connection state
Default policy What happens when nothing explicitly permits traffic

33. Ubuntu firewall: UFW

Install on a dedicated Ubuntu VM or server, not as a casual experiment on a critical host:

sudo apt install ufw
sudo ufw status
sudo ufw status verbose

A safe example policy to review and apply on an isolated VM:

sudo ufw allow from 192.168.10.0/24 to any port 22 proto tcp
sudo ufw allow 443/tcp
sudo ufw allow 80/tcp
sudo ufw allow 8080/tcp
sudo ufw default deny incoming
sudo ufw default allow outgoing

After confirming remote management remains permitted:

sudo ufw enable
sudo ufw status numbered

Illustrative output:

Status: active
[ 1] 22/tcp     ALLOW IN    192.168.10.0/24
[ 2] 443/tcp    ALLOW IN    Anywhere
[ 3] 80/tcp     ALLOW IN    Anywhere
[ 4] 8080/tcp   ALLOW IN    Anywhere

Remove the training port rule and disable if appropriate:

sudo ufw delete allow 8080/tcp
sudo ufw disable

Warning: Never enable restrictive firewall defaults on a remote production server until you are sure that administrator access is allowed. Cloud firewall policies and OS firewall rules are separate. Windows Firewall and Hyper-V firewall can also affect WSL traffic; use a VM to test predictable UFW enforcement.

34. Restrict database access

PostgreSQL database server: 192.168.10.30:5432. Only application server 192.168.10.20 should connect.

sudo ufw allow from 192.168.10.20 to any port 5432 proto tcp

Combined with a default-deny incoming policy, this permits that source. PostgreSQL must separately listen on the desired interface and enforce authentication; firewall allow is not database authorization.

Common mistakes: opening every port, unrestricted SSH, public database exposure, forgetting that services must listen, and overlooking cloud network security rules.

echo "127.0.0.1 portal.training.test" | sudo tee -a /etc/hosts

Step 8 — Browser test: Inside Ubuntu open http://portal.training.test:8080. From the Windows browser use http://localhost:8080; the Linux /etc/hosts entry does not automatically propagate to Windows.

Step 9 — Cleanup: Stop the Python server with Ctrl+C, then:

sudo sed -i '/^127\.0\.0\.1 portal\.training\.test$/d' /etc/hosts

Module 9 — Real Network Troubleshooting

38. Scenario: Employee reports "The website is not working"

Check the network from lower-level configuration toward the application, finding the first failing layer.

Case 1 — No valid IP address

ip -4 addr
ip link show

Investigate interface status, DHCP and physical/virtual network connectivity.

Case 2 — Gateway unreachable

ip route
ip route get 1.1.1.1

Inspect the chosen next hop and test it where ICMP is permitted.

Case 3 — IP connectivity works but website name fails

ping -c 2 1.1.1.1
dig example.com
getent hosts example.com

Investigate DNS configuration, reachable resolvers and local mapping.

Case 4 — DNS works but application fails

curl -I https://example.com
nc -vz 127.0.0.1 8080
ss -lntp '( sport = :8080 )'

Check whether the process is running, listening at the right address and port, and permitted by the firewall.

Case 5 — Connection times out

Possible reasons: firewall dropping packets, invalid route or return route, host down, security policy, or service bound to an unexpected address.

Case 6 — Connection refused

Often the host is reachable, but no service accepts the target port; an explicit firewall reject can look similar.

Case 7 — Slow application

ping -c 10 1.1.1.1
traceroute -n 1.1.1.1
curl -w '\nTotal time: %{time_total}s\n' -o /dev/null -s https://example.com

Distinguish latency, packet loss, DNS delays and application processing delays.

40. Final scenario: Explain everything together

Manager: An employee enters https://portal.company.example in a browser. Explain how the request reaches the application.

  1. DHCP: Laptop obtained IP address, subnet mask, gateway and DNS configuration.
  2. DNS: The laptop resolves the portal name to an IP address.
  3. IP Addressing: Source and destination addresses identify the communicating interfaces.
  4. Routing: Packets pass through a gateway and routers when the destination is outside the local subnet.
  5. NAT: A NAT gateway can translate addresses and possibly ports if the request crosses such a boundary.
  6. Ports: HTTPS normally uses TCP 443, or UDP 443 for HTTP/3.
  7. Firewall: Network and host firewall policies permit or deny traffic.
  8. Web Server: Server handles the request and sends a response.
  9. Browser: The employee sees the portal.

Recommended learning order: Complete IP addressing, DNS, ports and the local web-server lab first in Ubuntu/WSL. Study DHCP, NAT and routed multi-subnet scenarios with the company topology, then reproduce them in isolated virtual machines using a router/firewall VM. A single WSL instance cannot simulate every part of an enterprise network.
