2. VNet, subnets, NSG, public IP and NAT explained

What is VNet?

A VNet is like your own private company network (similar in purpose to an AWS VPC). Use CompanyABC-VNet and address space 10.10.0.0/16. This address space includes 10.10.0.0 through 10.10.255.255.

What is a subnet?

A subnet is a smaller network inside the VNet. For our Windows server use Server-Subnet with CIDR 10.10.1.0/24. A /24 contains 256 IP addresses; Azure reserves five, leaving 251 assignable addresses.

What is an NSG?

A Network Security Group contains stateful inbound/outbound rules evaluated by priority. It can be associated with a subnet or VM NIC. If both have NSGs, their rules must allow the traffic. Lower priority numbers take precedence.

TrafficPortSuggested sourceReason
RDPTCP 3389Your public IP /32Secure Windows desktop connection
HTTPTCP 80Internet (only for public IIS demo)Access sample website
HTTPSTCP 443Internet (after TLS configuration)Secure website
All other inbound internet trafficAllInternetDefault deny unless another rule permits it
Security: Never leave RDP 3389 open to 0.0.0.0/0 for a normal lab. Narrow the NSG's RDP source to your current public IP.

What is NAT Gateway?

Azure NAT Gateway provides outbound internet connectivity from a subnet using public outbound IP address resources. The Windows VM can download software or updates while remaining without its own public IP. NAT Gateway is not an inbound RDP gateway.

Private VM→Subnet NAT Gateway→Internet / Updates

In our first lab we do not create NAT Gateway. Add it later for a private-only VM outbound demonstration. Azure VNet connectivity and routing are not exactly the same as an AWS Internet Gateway model.

4. Create the Resource Group and VNet

Step A — Resource Group

  1. Open https://portal.azure.com.
  2. Search Resource groups and click Create.
  3. Choose your subscription.
  4. Enter RG-AzureVM-Lab.
  5. Select region Central India.
  6. Click Review + create → Create.

Step B — VNet and subnet

  1. Search for Virtual networks → Create.
  2. Resource Group: RG-AzureVM-Lab.
  3. Name: CompanyABC-VNet; Region: Central India.
  4. Under IP addresses use VNet address space 10.10.0.0/16.
  5. In the Subnets section choose Add subnet (or edit the proposed default subnet).
  6. Set subnet name Server-Subnet and subnet range 10.10.1.0/24.
  7. For the first lab leave NAT Gateway, NSG, route table and delegation unconfigured; they are optional at VNet creation.
  8. Review and create the VNet.
Expected result: CompanyABC-VNet contains Server-Subnet with the correct address range. You will select it during the VM wizard's Networking tab.

Availability options in plain English

  • None: Single VM; appropriate for a disposable classroom lab.
  • Availability zones: Place separate VMs across supported datacenter zones for zone resilience.
  • Availability set: Spread a set of classic VMs across fault/update domains.
  • VM Scale Set: Managed group of VMs; can scale horizontally.

A single VM in a single zone does not become highly available just by selecting that zone.

Method 1 — Direct RDP practical

  1. Open Virtual machines → CompanyABC-WinVM.
  2. Ensure its state is Running.
  3. Copy its Public IP address.
  4. Use Connect → RDP and download the .rdp file, or on Windows press Win + R and type mstsc.
  5. Enter the public IP, then sign in using azureadminlab and the password entered at creation.
  6. Verify the RDP certificate prompt corresponds to the intended server; continue as appropriate.
Expected: You see the Windows Server desktop and can open Server Manager and PowerShell.

Method 2 — Azure Bastion

Bastion provides managed private RDP/SSH access through the Azure Portal, without assigning a public IP to the VM. Choose VM → Connect → Bastion, deploy/select the service if necessary, then enter credentials and connect. Bastion SKU and availability vary; paid dedicated SKUs can incur substantial ongoing cost. Dedicated Bastion deployments use a subnet named AzureBastionSubnet, normally /26 or larger. Developer SKU has distinct deployment behavior and region restrictions.

Admin browser→Azure Bastion→Private Windows VM

Method 3 — VPN / ExpressRoute

With a Point-to-Site VPN, connect an individual laptop into Azure. With a Site-to-Site VPN, connect an office LAN to Azure. ExpressRoute provides provider-based private connectivity. Then RDP to the private address if routes and security rules permit.

Method 4 — Run Command

When RDP has trouble, try Virtual Machine → Operations → Run command → RunPowerShellScript, provided the VM Agent and permissions work.

Get-Service TermService
Get-WindowsFeature Web-Server

This does not open a desktop; it remotely executes commands.

7. IIS demonstration — host your first website

Install IIS in Windows

  1. Connect via RDP to the Windows VM.
  2. Open Server Manager → Manage → Add Roles and Features.
  3. Select Role-based or feature-based installation and the local server.
  4. Choose Web Server (IIS) and add required features.
  5. Click Next / Install.

Alternative: Run this in an elevated PowerShell window inside the VM:

Install-WindowsFeature -Name Web-Server -IncludeManagementTools

Test from inside the VM

Open a browser at http://localhost. You should see the IIS default welcome page.

Expose the website

  1. In Azure Portal open the VM's associated NSG → Inbound security rules.
  2. Add Allow TCP port 80 with a suitable priority (e.g., 300).
  3. For this public web demo, set source Internet only if public access is intended.
  4. In the laptop browser open http://<YOUR-VM-PUBLIC-IP>.
Expected: You see the IIS website from outside the VM.
Production web services should use HTTPS and certificates. If port 80 does not respond, check Azure NSG, Windows Firewall, IIS service status, binding, and the public IP.
8. Azure Monitor — CPU and performance
  1. Go to Virtual machines → CompanyABC-WinVM.
  2. Select Monitoring → Metrics.
  3. Select the VM host metrics namespace and Percentage CPU.
  4. Choose Average aggregation and time range, e.g. last 30 minutes.
  5. Review CPU trends. You can also monitor network and disk activity.

Host CPU metrics generally do not require an agent. Guest memory and detailed OS telemetry typically require suitable guest monitoring.

You can create an Azure Monitor alert if CPU exceeds a threshold, but an alert on one ordinary VM does not create another VM automatically. Use a suitable VM Scale Set for automatic horizontal scaling.

9. Vertical vs horizontal scaling

Vertical scaling — Scale up/down

Increase or decrease the size of one existing VM, for example from 2 vCPUs / 4 GiB RAM to 4 vCPUs / 16 GiB RAM, if those sizes are available.

Small VM→Large VM

Go to VM → Size → choose supported size → Resize. May require deallocation/restart.

Horizontal scaling — Scale out/in

Increase/decrease the number of VM instances serving the workload. Use VM Scale Sets, application deployment automation, and load balancing when appropriate.

2 VMs→3 VMs→5 VMs

Useful for web applications designed to run across multiple servers.

CPU hitting 80% on a single normal VM does not automatically resize it. An alert or automation would need to be configured separately. Native VMSS autoscale primarily changes instance count.
10. Virtual Machine Scale Set (VMSS), CPU and time-based autoscale

A VM Scale Set manages a set of VM instances. It can increase instances when load rises and remove them when demand falls. Start with Flexible orchestration for many current deployments, subject to support and requirements.

11. Create a VM Scale Set — step-by-step GUI

Create a new Scale Set for this demo instead of assuming the first standalone VM can simply be converted.

  1. Search Virtual machine scale sets → Create.
  2. Select RG-AzureVM-Lab.
  3. Name: CompanyABC-WebVMSS.
  4. Region: Central India.
  5. Choose Flexible orchestration when appropriate and supported.
  6. Select a compatible Windows Server image and a small supported VM size.
  7. Supply an administrator username and strong password.
  8. Select CompanyABC-VNet and a suitable application subnet.
  9. Configure initial capacity as 2 instances, where offered.
  10. Configure the load-balancing/networking arrangement appropriate for the app.
  11. Ensure application installation can be repeated automatically across every new instance (e.g., extension, image or deployment mechanism).
  12. Review and click Create.

Configure autoscale

  1. Open CompanyABC-WebVMSS.
  2. Find Scaling / the available autoscale configuration.
  3. Select custom autoscaling where offered.
  4. Minimum: 2; Maximum: 5; Default: 2.
  5. Add rule: CPU > 70% sustained for 10 minutes → Increase instance count by 1.
  6. Add rule: CPU < 30% sustained for 10 minutes → Decrease instance count by 1.
  7. Use a suitable cooldown (example 5 minutes) and save.
  8. Observe instances, autoscale activity and CPU charts.
Application readiness: Autoscale does not automatically copy a manually modified web page from VM 1 to a new VM 2, nor does it solve session persistence or shared data requirements. Use repeatable deployments and an appropriate shared-state architecture.

14. Training cost and cleanup precautions
  • Choose a small compatible Windows VM; confirm displayed estimated price before creating.
  • Enable Auto-shutdown at the end of class. Confirm the VM becomes Stopped (deallocated) to stop compute charges.
  • Managed disks and public IPv4 addresses can continue incurring charges while compute is deallocated.
  • Deploy Bastion, NAT Gateway, VPN Gateway, Load Balancer and multiple VMSS instances only when they are part of an active demonstration; examine their charges separately.
  • Use Cost Management → Budgets and spending alerts. A budget alert is not a hard spending cap.
  • At the end of the practical, delete unused lab resources. For a fully disposable lab, review the contents of RG-AzureVM-Lab and delete the Resource Group only when you are sure all resources within it can be removed.
Deletions are permanent for resources and data without appropriate backups. Check you are in the correct training subscription and Resource Group.
