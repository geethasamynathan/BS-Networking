MODULE 01

What is Shell Scripting?

A shell is a program that accepts commands and runs them. Bash is a widely used Linux shell. A shell script is a text file containing commands and programming logic that Bash executes in sequence.

User / Scheduled Job
↓
Shell Script (.sh)
↓
Bash Interpreter
↓
Linux Commands and Programs
↓
Files • Logs • Processes • Network • Reports

Example: Instead of manually checking disk usage, service status and website connectivity every day, a script can perform all checks and save the results to a file.

TermMeaning
TerminalWindow used to interact with the system
ShellCommand interpreter
BashShell and scripting language
ScriptA file containing commands
KernelCore operating-system component

Prepare the Ubuntu / WSL Lab

Open Ubuntu Terminal. All exercises use a directory in your Linux home folder so existing system files are not modified.

pwd
whoami
bash --version
mkdir -p ~/shell-lab/{scripts,data,logs,reports,backup}
cd ~/shell-lab
tree ~/shell-lab

If tree is not installed:

sudo apt update
sudo apt install tree curl iputils-ping iproute2 dnsutils -y
WSL note: systemctl requires systemd to be enabled in the WSL distribution. Some networking observations, routes and services differ from a standalone Linux VM.
MODULE 04

Create and Execute Your First Script

Create a file with nano or use the here-document shown below.

cat > ~/shell-lab/scripts/hello.sh <<'EOF'
#!/bin/bash
echo "Welcome to Linux Shell Scripting"
echo "User: $(whoami)"
echo "Current folder: $(pwd)"
date
EOF
bash ~/shell-lab/scripts/hello.sh
chmod +x ~/shell-lab/scripts/hello.sh
~/shell-lab/scripts/hello.sh
SyntaxPurpose
#!/bin/bashInterpreter declaration (shebang)
echoPrint text
$(whoami)Run a command and substitute its output
chmod +xGrant execute permission
bash hello.shRun through Bash (no execute bit required if readable)
./hello.shExecute directly (requires appropriate execute permission)

Expected output includes the welcome message, current username, current location and the current date; exact values will differ.

MODULE 05

Building Blocks: Variables, Input and Arguments

#!/bin/bash
APP_NAME=ShopEase
REPORT_DIR="$HOME/shell-lab/reports"
mkdir -p "$REPORT_DIR"
printf 'Application: %s\nReport folder: %s\n' "$APP_NAME" "$REPORT_DIR"

Variable names are assigned without spaces around =. Quote variable expansions such as "$REPORT_DIR" to preserve spaces safely.

# Save as greet.sh
#!/bin/bash
name=${1:-Guest}
echo "Hello, $name"
# Run: bash greet.sh Geetha

$(date +%F)Command substitution: today’s date
MODULE 06

Decisions, Exit Codes, Loops and Functions

Bash uses an exit status of 0 for success and nonzero for failure. Conditional statements can test commands directly.

#!/bin/bash
FILE="$HOME/shell-lab/data/products.csv"
if [[ -f "$FILE" ]]; then
  echo "File exists"
else
  echo "File missing"
fi
for department in HR IT Finance; do
  echo "Checking: $department"
done

check_file() {
  [[ -f "$1" ]] && echo "Found: $1" || echo "Missing: $1"
}
check_file "$HOME/shell-lab/data/products.csv"
SyntaxMeaning
if ... then ... else ... fiConditional branch
[[ -f file ]]Test whether a regular file exists
for ... do ... doneLoop through values
function_name() { ...; }Reusable function
&&Run next command only if previous succeeds
||Run next command only if previous fails
MODULE 07

Example 1: Automated File Backup

Scenario: A support engineer needs a dated copy of an application configuration file before maintenance.

cat > ~/shell-lab/data/app.conf <<'EOF'
ApplicationName=ShopEase
Environment=Test
Version=1.0
EOF
cat > ~/shell-lab/scripts/backup.sh <<'EOF'
#!/bin/bash
set -euo pipefail
SOURCE="$HOME/shell-lab/data/app.conf"
TARGET="$HOME/shell-lab/backup/app_$(date +%Y%m%d_%H%M%S).conf"
[[ -f "$SOURCE" ]] || { echo 'Source missing' >&2; exit 1; }
cp -- "$SOURCE" "$TARGET"
echo "Backup created: $TARGET"
EOF
bash ~/shell-lab/scripts/backup.sh
ls -lh ~/shell-lab/backup

Result: A timestamped configuration file appears in backup/. set -euo pipefail enables useful error checks, but it does not replace explicit validation or careful testing.

MODULE 08

Example 2: Log Error Report

Scenario: Investigate application errors without reading every line manually.

cat > ~/shell-lab/logs/application.log <<'EOF'
INFO Application started
INFO Database connected
ERROR Database timeout
WARNING High CPU usage
ERROR Order processing failed
INFO Application recovered
EOF
cat > ~/shell-lab/scripts/log-report.sh <<'EOF'
#!/bin/bash
LOG="$HOME/shell-lab/logs/application.log"
REPORT="$HOME/shell-lab/reports/errors.txt"
if [[ ! -f "$LOG" ]]; then echo 'Log missing' >&2; exit 1; fi
grep -n 'ERROR' "$LOG" > "$REPORT" || :
echo "Error count: $(grep -c 'ERROR' "$LOG" || true)"
cat "$REPORT"
EOF
bash ~/shell-lab/scripts/log-report.sh

Expected report: two numbered error records. grep exits with status 1 when there are no matches, so the script treats that as an acceptable empty result.

Networking Fundamentals for Troubleshooting

ConceptWhat it answersUseful command
IP addressWhat address does this machine have?ip -br addr
Default routeWhere does traffic go outside the local network?ip route
DNSCan a hostname resolve to an IP address?getent ahostsv4 example.com
ReachabilityCan the host answer ICMP echo?ping -c 2 -W 2 1.1.1.1
HTTP(S)Can the web service respond?curl -I --max-time 8 https://example.com
Listening portsWhich TCP/UDP ports are listening locally?ss -tuln
TCP portCan I connect to an explicit host:port?bash /dev/tcp or curl with protocol-specific check
Important: ICMP may be blocked even when the website works. DNS resolution, network connectivity, TCP connection and HTTP response are different checks. A network test should not treat every failed ping as a server outage.

MODULE 11

Networking Lab 2: Ping, HTTP and Listening Ports

ping -c 3 -W 2 1.1.1.1
ping -c 3 -W 2 example.com
curl -I --connect-timeout 3 --max-time 10 https://example.com
ss -tuln
ss -ltn

What to compare: If DNS fails, hostname-based ping and curl may fail while an IP-based ping works. If HTTP gives 403 or 500, the server was reached but returned an application or authorization error. If curl times out, check routing, firewall, proxy and service availability.

Do not assume a port is open from ss alone: it displays local listening sockets. For remote reachability, test from the client’s network as well.
MODULE 12

Networking Lab 3: Local HTTP Service

Start a temporary web server using Python if Python 3 is available. This avoids relying on an internet-facing website or a system service.

mkdir -p ~/shell-lab/data/web
printf "Shell networking lab\n" > ~/shell-lab/data/web/index.html
cd ~/shell-lab/data/web
python3 -m http.server 8088 --bind 127.0.0.1

Keep the first terminal running. Open a second Ubuntu terminal:

curl -I http://127.0.0.1:8088
curl http://127.0.0.1:8088
ss -ltn | grep 8088

The expected HTTP status is typically 200 OK. Stop the temporary server with Ctrl+C in the first terminal. If the port is occupied, choose another available port.

MODULE 13

Complete Networking & Troubleshooting Script

Scenario: An operations team wants one command that reports hostname, network interfaces, default route, DNS resolution, IP ping, HTTPS response and a local TCP port check. The script does not change system configuration.

cat > ~/shell-lab/scripts/network-health.sh <<'EOF'
#!/bin/bash
set -u

HOST='example.com'
PING_IP='1.1.1.1'
WEB_URL='https://example.com'
LOCAL_HOST='127.0.0.1'
LOCAL_PORT='8088'
REPORT_DIR="$HOME/shell-lab/reports"
mkdir -p "$REPORT_DIR"
REPORT="$REPORT_DIR/network_$(date +%Y%m%d_%H%M%S).txt"

log() { printf '%s\n' "$*" | tee -a "$REPORT"; }
log 'NETWORK HEALTH REPORT'
log "Date: $(date)"
log "Host: $(hostname)"

log '--- Interfaces ---'
ip -br addr | tee -a "$REPORT"
log '--- Routes ---'
ip route | tee -a "$REPORT"

log "--- DNS: $HOST ---"
if getent ahostsv4 "$HOST" >> "$REPORT"; then
  log 'DNS: PASS'
else
  log 'DNS: FAIL'
fi

log "--- Ping: $PING_IP ---"
if ping -c 2 -W 2 "$PING_IP" >> "$REPORT" 2>&1; then
  log 'ICMP: PASS'
else
  log 'ICMP: NO REPLY (may be blocked)'
fi

log "--- HTTPS: $WEB_URL ---"
http_code=$(curl -L -sS -o /dev/null -w '%{http_code}' \
  --connect-timeout 3 --max-time 10 "$WEB_URL" 2>> "$REPORT")
curl_status=$?
if [[ $curl_status -eq 0 ]]; then
  log "HTTP response code: $http_code"
else
  log "HTTPS: CONNECTION FAILED (curl exit $curl_status)"
fi

log "--- Local TCP: $LOCAL_HOST:$LOCAL_PORT ---"
if (echo > /dev/tcp/$LOCAL_HOST/$LOCAL_PORT) 2>/dev/null; then
  log 'TCP port: REACHABLE'
else
  log 'TCP port: NOT REACHABLE'
fi

log "Saved report: $REPORT"
EOF
chmod +x ~/shell-lab/scripts/network-health.sh
~/shell-lab/scripts/network-health.sh

Expected result: A text report is created under ~/shell-lab/reports/. Results depend on the internet connection, firewall and whether the local test server on port 8088 is running.

ResultMeaningNext investigation
DNS FAILHostname could not be resolvedResolver configuration; DNS server
ICMP NO REPLYEcho response absentCheck policy; test TCP/HTTPS instead
HTTPS CONNECTION FAILEDTransport, DNS, TLS or timeout errorRead curl diagnostic / proxy / certificate / route
HTTP 200HTTP request succeededCheck actual page/application behavior
HTTP 500Server returned internal errorInspect server-side application logs
TCP NOT REACHABLEConnection to local port failedStart test service; check listener/port
Learning point: The script uses functions, variables, conditions, redirection, exit codes, command substitution and tee in one realistic workflow.

MODULE 15

Scheduling Scripts: Cron (Optional)

A health-check script can be run periodically with cron if a cron service is installed and running. In WSL, scheduled jobs may not run while the distro is stopped.

crontab -e
# Run every day at 9:00 AM (server local time)
0 9 * * * /bin/bash /home/geetha/shell-lab/scripts/network-health.sh >> /home/geetha/shell-lab/logs/cron.log 2>&1

Replace /home/geetha with your own home path. Check the scheduler and script behavior before relying on it. For machines that may sleep or stop, use an appropriate host-level scheduler.
