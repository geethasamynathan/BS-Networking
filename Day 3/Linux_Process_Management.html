SECTION 01

1. What is a process in Linux?

A process is a running instance of a program. When you execute sleep 60, Linux launches the program, assigns a process ID (PID), and manages it until completion or termination.

sleep 60

Real-world examples include a running .NET Web API, Java application, database service, Python worker or Nginx server.

User enters command
sleep 60
↓
Bash launches program
↓
Linux kernel manages PID, memory and CPU
↓
Process runs or waits
↓
Process completes and returns exit status
TermMeaningExample
ProgramExecutable instructions stored on disk/usr/bin/sleep
ProcessRunning instance of a programsleep 60
ThreadExecution unit inside a process.NET worker thread
ServiceManaged background workloadnginx.service
DaemonLong-running background programsshd

Lab 1 – Your first process

Run a process in the foreground

sleep 60

The terminal is occupied for approximately 60 seconds. The command produces no normal output. Press Ctrl+C to interrupt it.

sleep 5
echo "Process completed"
Expected / illustrative output
Process completed

The message appears after the sleep command finishes. Foreground execution normally makes the shell wait.

SECTION 06

Lab 2 – Start a background process

sleep 300 &
Expected / illustrative output
[1] 3456

[1] is the shell job number; 3456 is an example PID. & starts the process asynchronously.

jobs -l
Expected / illustrative output
[1]+ 3456 Running                 sleep 300 &

Save a new process PID

sleep 300 &
PID=$!
echo "Started PID: $PID"
ps -p "$PID" -o pid,ppid,stat,comm
Expected / illustrative output
Started PID: 3470
    PID    PPID STAT COMMAND
   3470    3200 S    sleep

$! is the PID of the most recently started asynchronous command. S indicates interruptible sleep.

kill "$PID"
wait "$PID"
A background job is not automatically a managed system service. Earlier sleep jobs can be stopped with their own displayed PIDs or job IDs.

Use signal names instead of hard-coded signal numbers where possible. SIGKILL prevents application cleanup and should be a last resort.
SECTION 11

Lab 7 – Industry demo: Employee Processing Worker

Create a real Bash worker that repeatedly counts employee records, writes timestamps, logs errors, and handles termination.

Step 1 – Employee data

cat > output/employees.csv <<'EOF'
EmployeeID,Name,Department
101,Geetha,Training
102,Neha,HR
103,Ravi,IT
104,Jatin,Finance
105,Arun,IT
EOF

Step 2 – Worker script

cat > scripts/employee-worker.sh <<'EOF'
#!/bin/bash
BASE_DIR="$(cd "$(dirname "$0")/.." && pwd)"
DATA_FILE="$BASE_DIR/output/employees.csv"
running=true
stop_worker() {
    echo "$(date '+%F %T') INFO Shutdown requested"
    running=false
}
trap stop_worker TERM INT
echo "$(date '+%F %T') INFO Employee worker started"
echo "Worker PID: $$"
while "$running"; do
    if [ -f "$DATA_FILE" ]; then
        COUNT=$(tail -n +2 "$DATA_FILE" | wc -l)
        echo "$(date '+%F %T') INFO Processed $COUNT employee records"
    else
        echo "$(date '+%F %T') ERROR Employee file missing"
    fi
    sleep 10 &
    wait $!
done
echo "$(date '+%F %T') INFO Employee worker stopped"
EOF
StatementRole
#!/bin/bashUse Bash interpreter
BASE_DIRFind project folder
DATA_FILEInput CSV file
$$Current shell PID
trapRegister signal handler
whileRepeat cycle
tail -n +2Skip CSV header
wc -lCount data rows
sleep 10Delay between cycles
wait $!Wait for sleep child
dateAdd timestamps

Step 3 – Make it executable and run

chmod 755 scripts/employee-worker.sh
ls -l scripts/employee-worker.sh
./scripts/employee-worker.sh
Expected / illustrative output
2026-10-30 10:00:00 INFO Employee worker started
Worker PID: 5100
2026-10-30 10:00:00 INFO Processed 5 employee records
2026-10-30 10:00:10 INFO Processed 5 employee records

Press Ctrl+C to request a graceful shutdown.

Step 4 – Background with logging

./scripts/employee-worker.sh > logs/employee-worker.log 2>&1 &
PID=$!
echo "Worker PID: $PID"
ps -p "$PID" -o pid,ppid,stat,etime,args
tail -n 10 logs/employee-worker.log

Step 5 – Change the input and inspect logs

echo "106,Priya,HR" >> output/employees.csv
tail -f logs/employee-worker.log
Expected / illustrative output
INFO Processed 6 employee records

Press Ctrl+C to stop tail -f, which does not stop the worker. Return to the terminal that has PID saved:

kill -TERM "$PID"
wait "$PID"
ps -p "$PID"
The worker demonstrates processing cycles and log output. It reads and counts the CSV; it does not submit transactions or mark individual records as processed.

SECTION 13

Lab 9 – Manage the worker using systemd

A managed service can start at boot, run under a dedicated account, restart on failure, and expose logs using journalctl.

Step 1 – Check systemd

ps -p 1 -o comm=
Expected / illustrative output
systemd
If systemd is not PID 1 on WSL, it must be enabled in the WSL configuration before attempting this lab.

Step 2 – Create a restricted service account

sudo useradd --system --no-create-home --shell /usr/sbin/nologin empworker

Step 3 – Install the worker

sudo mkdir -p /opt/employee-worker/{scripts,output}
sudo cp scripts/employee-worker.sh /opt/employee-worker/scripts/
sudo cp output/employees.csv /opt/employee-worker/output/
sudo chown -R root:root /opt/employee-worker
sudo chmod 755 /opt/employee-worker
sudo chmod 755 /opt/employee-worker/{scripts,output}
sudo chmod 755 /opt/employee-worker/scripts/employee-worker.sh
sudo chmod 644 /opt/employee-worker/output/employees.csv

Step 4 – Create employee-worker.service

sudo tee /etc/systemd/system/employee-worker.service > /dev/null <<'EOF'
[Unit]
Description=Employee Processing Worker Demo
After=network.target

[Service]
Type=simple
User=empworker
Group=empworker
WorkingDirectory=/opt/employee-worker
ExecStart=/bin/bash /opt/employee-worker/scripts/employee-worker.sh
Restart=on-failure
RestartSec=5
NoNewPrivileges=true
ProtectSystem=full
ProtectHome=true

[Install]
WantedBy=multi-user.target
EOF
SettingPurpose
Type=simpleForeground service process
User/GroupRestricted service identity
WorkingDirectoryService working directory
ExecStartLaunch command
Restart=on-failureRestart after eligible failures
RestartSec=5Delay 5 seconds
NoNewPrivileges=trueDisallow gaining extra privileges
ProtectSystem=fullRestrict writes to core system areas
ProtectHome=trueProtect home directories
WantedBy=multi-user.targetEnable at multi-user startup

Step 5 – Reload and start

sudo systemctl daemon-reload
sudo systemctl start employee-worker
systemctl is-active employee-worker
Expected / illustrative output
active

Step 6 – Inspect service and logs

sudo systemctl status employee-worker --no-pager
sudo journalctl -u employee-worker -n 10 --no-pager
sudo journalctl -u employee-worker -f
Expected / illustrative output
● employee-worker.service - Employee Processing Worker Demo
Loaded: loaded (...; disabled)
Active: active (running)
Main PID: 6500 (bash)

INFO Employee worker started
INFO Processed 5 employee records

Press Ctrl+C to exit log-follow mode.

Step 7 – Enable and manage startup

sudo systemctl enable employee-worker
systemctl is-enabled employee-worker
sudo systemctl stop employee-worker
systemctl is-active employee-worker
sudo systemctl restart employee-worker
systemctl is-active employee-worker
On WSL, enabling a service starts it when the WSL distro boots; it does not keep WSL running indefinitely.

Lab 10 – Priority with nice and renice

nice -n 10 sleep 300 &
PID=$!
ps -p "$PID" -o pid,ni,comm
Expected / illustrative output
    PID  NI COMMAND
   7200  10 sleep
renice -n 15 -p "$PID"
ps -p "$PID" -o pid,ni,comm
Expected / illustrative output
    PID  NI COMMAND
   7200  15 sleep
kill "$PID"
wait "$PID"

Typical nice values range from -20 (higher priority) to 19 (lower priority). They influence scheduling and do not set a guaranteed CPU usage limit.

SECTION 17

Lab 13 – Troubleshoot a failed application

Scenario: the Employee Processing Worker has unexpectedly stopped. Check whether it is running, inspect journal entries, confirm resource availability, verify permissions, and restart only when appropriate.

systemctl status employee-worker --no-pager
systemctl show employee-worker -p MainPID
sudo journalctl -u employee-worker -n 30 --no-pager
top
free -h
df -h
ls -l /opt/employee-worker/scripts/employee-worker.sh
ls -l /opt/employee-worker/output/employees.csv
sudo systemctl restart employee-worker
systemctl is-active employee-worker
sudo journalctl -u employee-worker -n 5 --no-pager
A running process does not automatically imply application health. Real applications should also have health checks and meaningful business monitoring.
